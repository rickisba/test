# 实验环境与参数来源

平台配置依据当前英文 `GSA (9).pdf` 的Section V-A、Fig. 7和Table IV。
中文底稿不作为本版平台配置来源。本文件记录稿件描述与当前仿真实际使用的范围，
不把稿件中的平台描述视为当前代码已经完成硬件部署的证明。

## 英文稿描述的平台

| 项目 | 配置 |
|---|---|
| 区域与站点 | 北京、广州各2站点，共4站点 |
| 每站点 | 1台可编程交换机、4台GPU工作站 |
| 客户端 | 每区域4台，共8台；1 Gbps NIC、Ubuntu 20.04 |
| Type A工作站 | Xeon Gold 6248、128 GB内存、2×RTX 3090、Ubuntu 22.04 |
| Type B工作站 | 2×Xeon Silver 4510、512 GB内存、8×RTX 5090、Ubuntu 22.04 |
| 网关交换机 | Tofino Flnet S9180-32x、Intel Xeon 1527、16 GB内存、32×100 Gbps端口 |

| IP路由器 | 文稿描述为200 Mpps、100 Gbps端口 |

没有用GPU理论FP32值推算模型服务吞吐。英文稿中Type A/B与理论算力数值的对应关系需核对，
当前仿真使用用户给出的prefill日志数值，不依赖该理论算力段落。

## 子图(a)实际建模的子集

- 同一区域的两个逻辑模型服务池，每池4台同类工作站；4个本地客户端发起请求。
- 一个池提供Light模型服务，另一个池提供Pro模型服务。该模型放置是子实验设定，
  英文稿并未逐一指定所有工作站的模型映射。
- 每工作站prefill标定值为2823/581 tokens/s；每请求输入400 tokens、输出1 token。
- 四台同类设备独立服务的线性扩展是建模假设，不额外乘以GPU数量。
- 只使用Clients与Site 1/2之间的942/944 Mbps链路；不模拟跨域Region或Session机制。
- 主结果总名义到达率24 rps；预热60 s、统计300 s；3组独立种子。

完整配置、指标、假设和限制见实验README及
[`output/run_manifest.json`](../experiments/task_distribution/output/run_manifest.json)。

## 后续校准

日志prefill吞吐可能来自非饱和输入负载，未必是服务上限。应核对稳定饱和区间、
四副本聚合能力，并使用独立请求日志验证分配组成。真实TTFT/端到端误差还需排队、
调度、batch及首token时间戳；目前没有相应实测误差结论。
