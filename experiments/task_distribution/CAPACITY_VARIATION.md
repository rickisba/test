# 设备吞吐波动与纵轴定义

本文件对应设备级波动敏感性仿真。所有幅度、相关时间和共同成分均为明确的建模假设，不是从2823/581两个平均吞吐量推断的实测参数。主图的恒定吞吐参照保持不变。

## 1. 纵轴到底统计什么

设输入的site 2专属精确请求数为P2，其中分配至site 2的数量为P22，分配至site 2的全部请求数为A2。当前主图纵轴是P22/A2×100%，表示site 2收到的任务组成。用户所问“发送的precise任务有多少送入site 2”对应P22/P2×100%，是另一个指标。

例如2个指定site 2的精确任务和3个模糊任务全部分配至site 2，主图是2/5=40%，而精确任务到指定站点的分配率是2/2=100%。两者分母不同。

CSV字段映射：

| 字段 | 分母与含义 |
|---|---|
| `precise_at_site2_pct` | P22/A2，主图的站内组成 |
| `site2_precise_sent_to_site2_pct` | P22/P2，目的站点分配率；sent在此仅指分配目的地 |
| `site2_precise_prefill_completed_by_window_end_pct` | 统计期内到达且在窗口结束前于正确站点完成prefill的site 2精确请求数/P2 |
| `precise_model_assignment_accuracy_pct` | 所有精确请求正确分配至各自指定模型的比例 |

没有site 2精确请求时，后两个以P2为分母的百分比为空，而不人为写成0%或100%。没有任何精确请求的回放同样将精确匹配准确率记为空，修复原来的除零问题。

模型允许排队、不设置拒绝或超时，所以L3GSA的精确目的站点分配率由资格规则保证为100%；不能将其当作真实网络送达率或业务成功率。窗口完成比例也只描述本模型的prefill事件与边界截断，不代表真实时延SLA或端到端可靠性。

## 2. 为什么四台设备仍可能接近100%

site 2容量份额为581/(2823+581)≈17.07%。名义总到达率24 rps下，容量均衡对应的分配份额约4.096 rps；末点4.8 rps已经是必须发往site 2的精确需求。因此在线选择倾向于将模糊请求分配至site 1，site 2的任务组成可以接近全部precise。此时4.8/5.81≈82.62%，并不等于site 2满负荷或请求全部及时完成。

在等均值、等方差且相互独立的设备波动下，4台设备合计吞吐的CV约为单设备的一半。站点内共同波动则不会被这4台设备相互抵消。因此“有4台设备且存在波动”本身不能推导出站内precise占比必然显著低于100%。

## 3. 波动模型与公平性

每台工作站的实际处理速率由均值为名义标定值的平稳对数正态过程驱动，时间相关使用AR(1)，采样间隔1 s、相关时间5 s。单设备目标CV分别为5%或10%，表示标准差/均值，不是±5%/±10%的硬界限。

过程包含每站点共同成分和每设备独立成分。共同成分占对数方差的0、50%、100%；它不是精确的吞吐相关系数。两个站点的共同成分彼此独立。四台设备的有效容量始终按当时的实际速率相加。

速率事件影响正在处理的剩余工作量、完成时刻和排队；动态路由仍只使用已到达的容量报告。每组内各条件、各策略复用相同速率轨迹；容量采用独立随机流，原请求到达时刻、类别排序和静态随机数不变。没有对每条轨迹进行事后重定心、截断或选种子，有限窗口的平均速率可以偏离名义值。

## 4. 新的三组仿真结果

以下是L3GSA站内组成的均值[min,max]，单位%。各场景均单独运行3组，不合并为15组误差棒。

| 波动场景 | 2.4 rps | 3.6 rps | 4.8 rps |
|---|---:|---:|---:|
| 恒定吞吐 | 59.233 [59.002, 59.432] | 85.243 [84.597, 85.759] | 99.470 [99.303, 99.586] |
| 单设备CV 5%，独立 | 59.395 [59.195, 59.557] | 85.198 [84.465, 85.894] | 99.242 [98.835, 99.589] |
| 单设备CV 10%，独立 | 59.317 [58.809, 59.732] | 84.623 [83.617, 85.490] | 98.859 [98.095, 99.249] |
| 单设备CV 10%，一半对数方差共同 | 59.202 [58.553, 60.149] | 83.854 [83.048, 85.090] | 98.741 [98.139, 99.181] |
| 单设备CV 10%，站点内完全共同 | 58.473 [57.466, 59.901] | 82.654 [81.776, 83.717] | 98.270 [97.268, 98.844] |

在本组假设下，设备独立波动10%的末点仍约98.86%，完全共同波动10%时约98.27%。存在吞吐波动并不要求组成大幅下降。5%/10%仍只是敏感性场景，当前没有设备时间序列可以判定哪一项最接近实际平台。

恒定容量的原始主图数值保持不变；不将波动结果直接替换为正式论文主结果。理想参考柱继续基于名义容量，不是随机场景的逐时最优值或一般上界。

## 5. 复现与数据

```bash
python simulate_allocation.py --sensitivity --capacity-variation
python validate_model.py
```

`output/capacity_variation_summary.csv`汇总三方案的组成、目的站点分配率和窗口prefill完成比例。每个场景目录保留3×4×3个分轮计数、绘图CSV、配置与设备/站点的实际时间加权均值和CV。原始每秒设备速率写入`capacity_traces.csv`，可由种子复现，不重复提交Git。

如需查看单个波动场景的图，仍使用同一个独立绘图脚本，无需样式JSON：

```bash
python plot_allocation.py --data output/capacity_variation/device_cv10_independent/plot_data.csv --out figures
```

测量窗口为60至360 s；最后一个速率样本之后排空队列时保持该样本。主图统计固定的到达队列成员，不能用排空后的全部完成来宣称统计期内完成率100%。
